--- title: Embedding description: Put the globe on your own site with one line — the map of a chapter, a place, a year or a tour — and control it from your page. ---

The globe runs inside any page as an iframe. One line shows the map of a chapter next to the passage on your page; a few messages keep the two in step.

Quick start

<iframe
  src="{{site}}/embed/v1?ref=Acts.16&locale=en"
  title="Map of Acts 16"
  style="width: 100%; height: 480px; border: 0; border-radius: 12px"
  allow="fullscreen"
  loading="lazy"
></iframe>
  • The map fills the frame and opens on the places of Acts 16, in the year of its events.
  • Top: the chapter. Select it to list its places in the order the text names them; select a place to open its card.
  • Bottom: the year. Select it to open the time slider.
  • A link opens the same view in the full globe in a new tab. Credits are shown on the map itself, as the data licences require.
  • The frame works down to a phone’s width; a height of 480 px is enough.

A chapter or a passage

ref takes an OSIS reference with English book abbreviations and English verse numbering:

Value Shows
Acts.16 a chapter
Gen.12-Gen.13 up to three chapters
Acts.16.11-Acts.16.15 a passage
Ruth a whole book

The map moves to the year of the passage: the recorded year of its chapters (chapters of {{chapter_books}} books are dated), or else the year of the tour that covers it; a whole book takes the year of the tour with the most stops in it. A passage with neither keeps the map’s current year.

Parameters

Parameter Example Meaning
ref Acts.16 chapter, passage or book (above)
year -999 year, in astronomical numbering: 1 BC is 0, 1000 BC is -999
place af2161c open a place (here, Capernaum); IDs are described under Place IDs
tour paul-1 start a guided tour
stop 3 with tour: open it at that stop
lesson a15257a~30.a112427~30 your own lesson, with tour=lesson: place IDs in order, each with the year to show it at (~-585 for 586 BC: as year, 1 BC is 0); every stop gets the place’s verse nearest that year, the distance, the time on foot and the relief. The “Add to a lesson” button on a place card builds the same links
title Paul%20in%20Galatia with lesson: the lesson’s name, up to 80 characters, at the head of its tour and its printed sheet
locale en language, one of {{locale_codes}}
camera 35.2,31.8,7,30,0 longitude, latitude, zoom, pitch, bearing; with place, the map opens at this camera with the place selected, instead of flying to it
measure a15257a,aaf03fa two place IDs: the distance tool open between them; a small frame and ui=map show only the line
ui map the map alone, for a page with its own search and place box: no place card, no chapter bar, the year folded; the link to the globe stays. The selected place is marked with a ring, and a click on the map away from any place clears the selection (see the example)
hide relief,battles layers to turn off: borders, places, relief, routes, roads, battles

The easiest way to build a view is to set it up on the full globe and copy the URL: the same parameters work after /embed/v1.

Messages

The globe and your page communicate through postMessage. Every message is an object with type and v: 1. The globe sends only what happens on the map and never anything that identifies the reader, so it posts to the parent page whatever its origin (target "*"); it accepts messages only from the page that holds the frame.

From the globe

Type Payload When
hg:ready { view } the map is drawn
hg:view-changed { view } the year, place, tour or camera has changed and settled (about 400 ms after the last change), whether the reader or your hg:set-view changed it. When the map flies to a newly selected place, it comes once with the new place and the camera the map left, then again when the flight ends
hg:place-clicked { place } the reader clicked a place on the map, the place already selected too; it comes before the hg:view-changed that the click causes
hg:verse-clicked { osis } the reader clicked a verse in a place card, e.g. "Acts.16.12"
hg:error { code, message } the map or its data could not load: code is "map" or "data"

view holds year, locale and layers and, when set, place, tour, stop, ref and camera. A view without place means that no place is selected. camera is an object, { center: [35.2, 31.8], zoom: 7, pitch: 30, bearing: 0 }, not the string of the address; layers gives each layer true or false: { relief: false, battles: false }.

To the globe

Type Payload Effect
hg:set-view { view } set the year, chapter (ref), place, layers or camera; with tour (and stop), the tour starts and the other fields are ignored; the language changes only with hg:set-locale. place: null clears the selection and ends a tour that is running. The place already selected is flown to again, unless the view also has camera. A place ID that the map does not have is ignored
hg:set-locale { locale } switch the language
  • Wait for hg:ready before you send anything: a message sent while the map is still loading is lost.
  • Treat hg:view-changed as the current state, not as something the reader did: it follows your own hg:set-view and every move of the camera. A page that sends the whole view back as it was told it, camera included, starts neither a loop nor a flight. Do not answer hg:view-changed with hg:set-view and a place alone: without camera, the map flies back to that place, away from where the reader moved it.

Place IDs

A place of the Bible has OpenBible’s ID: a followed by six hexadecimal digits, such as af2161c (Capernaum). The places of the ancient world that the Bible does not name (Gamla, Sepphoris, Pompeii) have their Pleiades number instead (Gamla is 678146) or, without one, their Wikidata item (Constantinople is Q16869). Both kinds can come in view.place and hg:place-clicked, and both are accepted by hg:set-view; if your data has only OpenBible’s places, test the form before you look one up. Of OpenBible’s {{openbible}} places, {{absent}} are not on the map (left out, or with no point at all); their IDs are ignored.

Example: the map follows your reader

const globe = document.querySelector("iframe").contentWindow;

// When your reader opens a chapter, show it on the map.
function showChapter(osis) {
  globe.postMessage({ type: "hg:set-view", v: 1, view: { ref: osis } }, "*");
}

// When a verse is clicked on the map, open it in your reader.
window.addEventListener("message", (e) => {
  if (e.source !== globe) return;
  if (e.data?.type === "hg:verse-clicked") openVerse(e.data.osis);
});

Example: the map beside your own place box

<iframe src="{{site}}/embed/v1?ui=map&place=af2161c&locale=en" title="Map"></iframe>
const globe = document.querySelector("iframe").contentWindow;
let ready = false;

window.addEventListener("message", (e) => {
  if (e.source !== globe) return;
  const m = e.data;
  if (m?.type === "hg:ready") ready = true;
  // The view as it is now: a place selected, or none. Comes often: showPlace should do
  // nothing when that place is already shown.
  if (m?.type === "hg:ready" || m?.type === "hg:view-changed") {
    if (m.view.place) showPlace(m.view.place);
    else hidePlace();
  }
  // Every click on a place, the one already selected too: open your box again.
  if (m?.type === "hg:place-clicked") showPlace(m.place);
});

// Your search picked a place: select it and fly to it (again, if it is selected already).
function pickPlace(id) {
  if (ready) globe.postMessage({ type: "hg:set-view", v: 1, view: { place: id } }, "*");
}

// Your box was closed: clear the selection on the map.
function closeBox() {
  if (ready) globe.postMessage({ type: "hg:set-view", v: 1, view: { place: null } }, "*");
}
  • The selected place is marked with a ring that grows and fades, so the eye finds it without anything covering the map; for a reader who has asked for less motion the ring stays still.
  • A click on the map away from any place clears the place selection; a tour that is running goes on. A double-click (which zooms) and a click that stops the moving map clear nothing. place: null from your page clears the place and ends the tour.
  • A tour runs on the map (its route, its stops and the year) without its card: your page moves it with hg:set-view and { tour, stop }. measure draws its line, as in every frame.
  • hg:verse-clicked is not sent: the verses are in the place card, which this mode leaves out.

Places in any text

One more line links the Bible places that your own text names (an article, a sermon, a reading plan) to the globe. Point at a name, or tap it on a phone, and a card shows what the place is, where it is today, how many verses name it and where it lies on the map; the card leads to the globe. 

<script src="{{hgPlacesSrc}}" integrity="{{hgPlacesIntegrity}}" crossorigin="anonymous" data-scope="article" charset="utf-8" defer></script>

The address carries a version, and the integrity hash pins its exact content: the browser runs the script only if it is that very file. A new version gets a new address; the old ones stay as they are.

Attribute What it does
data-scope where to look, as a CSS selector; the whole page by default
data-locale the language of the text, one of the site's languages: {{locale_codes}}; by default the page's lang; any other language falls back to English
data-every link every mention, not only the first of each place
data-theme light or dark for the card; by default it follows the reader's system

Only names that point to one place are linked. A name shared by two places (Antioch, of Syria and of Pisidia), by a place and a person (Judah), or by a place and an ordinary word stays plain text, and so does a name the Bible’s own verses mostly use for something else (“Kadesh” there is Kadesh-barnea, not the Kadesh of the database). A place’s name that is also a first name (Jordan, Sharon) is left alone next to another capitalised word: Jordan Smith is a person, not the river. In Russian, Ukrainian, Polish, Czech, Serbian, Hungarian, Finnish and Romanian, names are found in their inflected forms (“в Египте”, “w Jerozolimie”, “v Jeruzalémě”), and German, Swedish, Danish and Norwegian names in the genitive too (“Jerusalems”). Links, code, form fields, buttons and headings are left alone.

The script has no dependencies and sets no cookies. It reads one file of names from the globe (about {{names_kb_min}} to {{names_kb_max}} KB over the network depending on the language, plus {{script_kb}} KB of script), without your page's address as referrer, and changes only the names it links. It works under a strict Content Security Policy that allows the globe's address in script-src and connect-src. For text your page adds later, call HistoryGlobePlaces.scan(element) once the text is rendered: the script splits text nodes, so in a React or Vue page run it on content the framework no longer re-renders.

Stability

/embed/v1 is a contract: within v1, parameters and messages are only added, never changed or removed. A breaking change will ship as /embed/v2, and v1 will keep working.
